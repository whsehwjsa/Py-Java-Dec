# 命令使用说明

本文档详细介绍如何通过命令行方式使用Java反编译工具，包括基本用法、参数配置、高级选项和常见问题解决方法。

## 基本运行命令

### 主入口脚本

通过`main.py`脚本作为主入口点运行反编译工具：

```bash
python main.py <input_path> [选项]
```

其中`<input_path>`可以是：
- 单个JAR文件路径
- 单个Class文件路径
- 包含JAR/Class文件的目录路径
- 使用通配符的路径模式（如`*.jar`或`dir/*`）

### CLI模块运行

也可以通过CLI模块直接运行：

```bash
python -m java_decompiler.cli <input_path> [选项]
```

## 命令行参数详解

### 核心参数

- `<input_path>`: 输入文件或目录路径（必需参数）
- `--output`, `-o`: 输出目录路径（默认为`decompiled_output`）
- `--engine`, `-e`: 反编译引擎选择，可选值：`cfr`（默认）、`fernflower`、`jadx`
- `--recursive`, `-r`: 递归处理子目录中的文件（布尔值，默认为false）
- `--deobfuscate`, `-d`: 启用反混淆功能（布尔值，默认为false）

### 日志与调试参数

- `--verbose`, `-v`: 显示详细的反编译过程信息（布尔值，默认为false）
- `--debug`, `-D`: 启用调试模式，显示更多日志信息（布尔值，默认为false）
- `--version`, `-V`: 显示程序版本信息并退出
- `--help`, `-h`: 显示帮助信息并退出

### 配置与设置参数

- `--config`: 指定配置文件路径
- `--dump-config`: 显示当前配置并退出
- `--version-info`: 显示程序版本和系统信息并退出

### 引擎特定参数

- `--cfr-path`: CFR JAR文件路径（如果未在配置中指定）
- `--fernflower-path`: FernFlower JAR文件路径（如果未在配置中指定）
- `--jadx-path`: JADX可执行文件或JAR文件路径（如果未在配置中指定）
- `--tool-options`: 反编译工具的额外选项，格式为`key1=value1,key2=value2`

## 反编译引擎选择方法

可以通过以下三种方式指定反编译引擎：

### 1. 命令行参数方式（优先级最高）

```bash
python main.py example.jar --engine fernflower
```

### 2. 环境变量方式

通过设置环境变量`JAVA_DECOMPILER_ENGINE`来指定默认引擎：

**Linux/macOS系统**：
```bash
JAVA_DECOMPILER_ENGINE=jadx python main.py example.jar
```

**Windows系统**：
```batch
set JAVA_DECOMPILER_ENGINE=jadx
python main.py example.jar
```

### 3. 配置文件方式（优先级最低）

在项目配置文件中设置默认引擎。

## 引擎路径配置

如果反编译引擎的JAR文件或可执行文件不在默认位置，可以通过以下方式指定路径：

### 1. 命令行参数方式

```bash
python main.py example.jar --cfr-path /path/to/cfr.jar
```

### 2. 环境变量方式

**Linux/macOS系统**：
```bash
JAVA_DECOMPILER_CFR_PATH=/path/to/cfr.jar python main.py example.jar
```

**Windows系统**：
```batch
set JAVA_DECOMPILER_CFR_PATH=C:\path\to\cfr.jar
python main.py example.jar
```

### 3. 配置文件方式

在项目配置文件中设置引擎路径。

## 高级配置选项

### 输出控制选项

- `--output-format`, `-f`: 指定输出格式，支持`java`（默认，输出.java文件）和`zip`（压缩输出）
- `--output-name`, `-n`: 自定义输出文件名（对于单个文件输入）
- `--preserve-package`, `-p`: 保留原始包结构（布尔值，默认为true）
- `--overwrite`, `-O`: 允许覆盖现有文件（布尔值，默认为false）

### 性能优化选项

- `--memory-limit`, `-m`: 限制Java进程的最大内存使用量（以MB为单位）
- `--timeout`, `-t`: 设置反编译超时时间（以秒为单位，默认300秒）
- `--multithread`, `-M`: 启用多线程处理（适用于批量反编译，布尔值，默认为false）
- `--thread-count`, `-T`: 指定线程数量（当启用多线程处理时，默认为CPU核心数）
- `--profile`: 启用性能分析（使用cProfile，布尔值，默认为false）
- `--profile-output`: 指定性能分析输出文件路径

### 引擎特定高级选项

不同引擎支持不同的特定选项，可以通过`--tool-options`参数传递：

#### CFR引擎选项示例

```bash
python main.py example.jar --tool-options "rename=true,showversion=false,caseinsensitive=true"
```

常用CFR选项：
- `rename`: 启用标识符重命名（true/false）
- `showversion`: 显示CFR版本信息（true/false）
- `caseinsensitive`: 大小写不敏感匹配（true/false）

#### FernFlower引擎选项示例

```bash
python main.py example.jar --engine fernflower --tool-options "dgs=1,hes=0"
```

常用FernFlower选项：
- `dgs=1`: 禁用语法糖（1表示禁用，0表示启用）
- `hes=0`: 隐藏合成元素（1表示显示，0表示隐藏）

#### JADX引擎选项示例

```bash
python main.py example.jar --engine jadx --tool-options "deobf=1,deobf-min=4"
```

常用JADX选项：
- `deobf=1`: 启用反混淆（1表示启用，0表示禁用）
- `deobf-min=4`: 设置最小标识符长度
- `deobf-use-sourcename=1`: 使用源文件名称作为类名（如果可用）
- `deobf-cfg=1`: 生成反混淆配置文件

## 性能优化最佳实践

### 1. 大型JAR文件处理

对于大型JAR文件，建议增加内存限制和超时时间：

```bash
python main.py large_application.jar --memory-limit 4096 --timeout 600
```

### 2. 批量处理优化

对于批量处理多个JAR文件，使用多线程可以显著提高性能：

```bash
python main.py jars_directory --recursive --multithread --thread-count 4
```

### 3. 提高速度的方法

- 对于不需要反混淆功能的场景，可以明确禁用它

  ```bash
  python main.py example.jar --deobfuscate false
  ```

- 对于不需要完整包结构的场景，可以使用非递归模式

  ```bash
  python main.py jars_directory --recursive false
  ```

## 故障排除指南

### 启用详细日志

当遇到问题时，首先尝试启用详细日志输出：

```bash
python main.py example.jar --verbose --debug
```

### 内存问题处理

如果出现内存不足错误，可以尝试：

1. 增加Java进程的内存限制

   ```bash
   python main.py example.jar --memory-limit 4096
   ```

2. 对大型JAR文件，考虑分批处理

3. 使用JADX引擎，通常内存效率更高

## 常见问题与解决方案

### 1. 反编译失败

**问题**：无法反编译某些JAR文件或Class文件

**解决方案**：
- 尝试使用不同的反编译引擎（建议JADX作为备选）
- 增加内存限制和超时时间
- 检查Java环境是否正确配置且版本不低于8
- 使用`--verbose --debug`参数获取详细错误信息

### 2. 内存不足

**问题**：处理大型JAR文件时出现内存不足错误

**解决方案**：
- 增加`--memory-limit`参数值（如`--memory-limit 8192`）
- 分批处理大型JAR文件
- 使用JADX引擎（通常内存效率更高）
- 关闭不必要的反混淆选项

### 3. 反混淆效果不佳

**问题**：反混淆后的代码仍然难以理解

**解决方案**：
- 使用JADX引擎并启用其高级反混淆选项
- 尝试不同的反混淆参数组合，如：

  ```bash
  python main.py obfuscated_app.jar --engine jadx --deobfuscate --tool-options "deobf=1,deobf-min=4,deobf-use-sourcename=1,deobf-cfg=1"
  ```
- 对特别复杂的混淆代码，可能需要手动分析和调整

### 4. 输出目录冲突

**问题**：指定的输出目录已存在，导致文件覆盖或错误

**解决方案**：
- 指定一个不存在的输出目录
- 使用`--overwrite`参数允许覆盖现有文件
- 使用`--output-name`参数为每个反编译任务指定不同的输出名称

## 高级自动化使用场景

### 批量处理多个JAR文件

对于需要处理大量JAR文件的场景，可以结合操作系统的批处理功能：

**Windows批量处理示例**：

```batch
@echo off
for %%f in ("jars\*.jar") do (
    echo 处理 %%f
    python main.py "%%f" --output "output\%%~nf" --multithread
)
```

**Linux/macOS批量处理示例**：

```bash
for jar_file in jars/*.jar; do
    echo "处理 $jar_file"
    python main.py "$jar_file" --output "output/$(basename "$jar_file" .jar)" --multithread
done
```

### 高度混淆代码的反编译与调试

对于混淆严重的代码，结合使用JADX引擎和多种反混淆选项：

```bash
python main.py obfuscated_app.jar \
    --engine jadx \
    --deobfuscate \
    --tool-options "deobf=1,deobf-min=4,deobf-use-sourcename=1,deobf-cfg=1" \
    --output deobfuscated_app
```

# 运行静态分析工具...
