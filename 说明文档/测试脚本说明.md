# Java反编译工具 - 测试脚本说明

本文档介绍Java反编译工具提供的测试脚本，包括单元测试和功能测试的使用方法、测试内容及常见问题排查。

## 概述

Java反编译工具项目包含两个主要的测试脚本：

1. **test_functions.py** - 单元测试脚本，用于验证核心功能的正确性
2. **simple_function_test.py** - 功能测试脚本，用于测试实际的反编译功能

## 单元测试 (test_functions.py)

### 功能特点

单元测试脚本基于Python的`unittest`框架开发，主要用于测试：

- 核心功能函数的正确性
- 边界条件的处理
- 异常处理机制
- 参数验证

### 运行方法

```bash
# 在项目根目录下运行所有单元测试
python -m unittest tests/test_functions.py

# 或运行特定的测试类
python -m unittest tests.test_functions.TestCFRDecompiler

# 或运行特定的测试方法
python -m unittest tests.test_functions.TestCFRDecompiler.test_decompile_file

# 启用详细输出模式
python -m unittest -v tests/test_functions.py
```

### 测试内容

测试脚本包含以下测试类和测试方法：

#### TestCFRDecompiler

- `test_decompile_file` - 测试CFR引擎反编译单个文件的功能
- `test_decompile_directory` - 测试CFR引擎反编译目录的功能
- `test_invalid_input` - 测试CFR引擎处理无效输入的行为
- `test_timeout` - 测试CFR引擎的超时机制

#### TestFernFlowerDecompiler

- `test_decompile_file` - 测试FernFlower引擎反编译单个文件的功能
- `test_decompile_directory` - 测试FernFlower引擎反编译目录的功能
- `test_invalid_input` - 测试FernFlower引擎处理无效输入的行为

#### TestJADXDecompiler

- `test_decompile_file` - 测试JADX引擎反编译单个文件的功能
- `test_decompile_directory` - 测试JADX引擎反编译目录的功能
- `test_deobfuscate_option` - 测试JADX引擎的反混淆功能

#### TestCodeFormatter

- `test_format_file` - 测试代码格式化功能
- `test_format_directory` - 测试目录格式化功能
- `test_invalid_format_input` - 测试格式化无效输入的行为

#### TestDependencyAnalyzer

- `test_analyze_file` - 测试单文件依赖分析功能
- `test_analyze_directory` - 测试目录依赖分析功能
- `test_build_dependency_graph` - 测试构建依赖图功能

#### TestCodeSearcher

- `test_search_files` - 测试基本搜索功能
- `test_search_class_definitions` - 测试搜索类定义功能
- `test_search_method_definitions` - 测试搜索方法定义功能

## 功能测试 (simple_function_test.py)

### 功能特点

功能测试脚本主要用于测试实际的反编译功能，更接近实际使用场景，包括：

- 完整的反编译工作流程测试
- 多引擎对比测试
- 不同类型输入（JAR、Class文件、目录）的处理
- 反编译后代码质量的验证

### 命令行参数

功能测试脚本支持以下命令行参数：

| 参数 | 描述 | 必需 | 默认值 |
|------|------|------|--------|
| `--input`, `-i` | 输入路径（文件或目录） | 是 | - |
| `--output`, `-o` | 输出目录路径 | 否 | `test_output` |
| `--engine`, `-e` | 反编译引擎选择 | 否 | `all` |
| `--deobfuscate`, `-d` | 是否启用反混淆 | 否 | `False` |
| `--verbose`, `-v` | 显示详细输出 | 否 | `False` |
| `--compare`, `-c` | 比较不同引擎的输出结果 | 否 | `False` |
| `--validate`, `-a` | 验证反编译结果的有效性 | 否 | `False` |

### 使用示例

```bash
# 使用默认参数测试反编译
python simple_function_test.py --input sample.jar

# 指定输出目录和引擎
python simple_function_test.py --input sample.jar --output my_test_output --engine jadx

# 使用所有引擎并比较结果
python simple_function_test.py --input sample.jar --engine all --compare --verbose

# 启用反混淆并验证结果
python simple_function_test.py --input obfuscated.jar --deobfuscate --validate
```

### 测试流程

1. 验证输入路径是否存在
2. 创建输出目录（如果不存在）
3. 根据指定的引擎执行反编译操作
4. 可选：比较不同引擎的输出结果
5. 可选：验证反编译结果的有效性
6. 生成测试报告

### 测试报告

测试完成后，会在输出目录中生成一个`test_report.txt`文件，包含以下信息：

- 测试基本信息（时间、参数等）
- 反编译统计数据（文件数、成功率、耗时等）
- 错误和警告信息（如有）
- 引擎比较结果（如启用比较）
- 验证结果（如启用验证）

## 测试准备

在运行测试前，请确保：

1. 已安装Java运行时环境（JRE 8+或JDK 8+）
2. 已安装必要的Python依赖：
   ```bash
   pip install tqdm  # 用于进度显示
   ```
3. 测试文件准备：
   - 准备一些Java类文件或JAR文件用于测试
   - 确保这些文件没有版权问题

## 测试结果解读

### 单元测试结果

单元测试结果通常显示为：

- `.` - 测试通过
- `F` - 测试失败
- `E` - 测试错误
- `s` - 测试跳过

例如：
```
.......F....
```
表示执行了12个测试，其中11个通过，1个失败。

### 功能测试结果

功能测试会在控制台显示进度和结果摘要，详细信息会保存到测试报告文件中。主要关注以下指标：

- **成功率** - 成功反编译的文件数占总文件数的百分比
- **平均耗时** - 每个文件的平均反编译时间
- **错误类型** - 常见错误及其分布
- **结果差异** - 不同引擎输出结果的差异（如启用比较）

## 常见问题排查

### Java环境问题

- **错误信息**：`Error: Unable to find Java executable`
- **解决方案**：确保Java已正确安装，并添加到系统PATH环境变量中

### 内存不足

- **错误信息**：`Java heap space` 或 `OutOfMemoryError`
- **解决方案**：增加Java的内存分配，使用`memory_limit`参数

### 超时错误

- **错误信息**：`TimeoutError`
- **解决方案**：增加超时时间，使用`timeout`参数

### 文件权限问题

- **错误信息**：`PermissionError` 或 `Access denied`
- **解决方案**：确保有足够的权限访问输入文件和写入输出目录

### 不支持的文件格式

- **错误信息**：`Unsupported file format`
- **解决方案**：确保输入文件是有效的Java类文件或JAR文件

## 自定义测试

如果需要添加自定义测试，可以：

1. 在`tests`目录中创建新的测试文件
2. 继承`unittest.TestCase`类
3. 添加以`test_`开头的测试方法
4. 使用`assert`语句验证结果

示例：

```python
import unittest
from java_decompiler.decompilers import CFRDecompiler

class TestCustomFeatures(unittest.TestCase):
    
    def test_custom_option(self):
        # 创建测试实例
        decompiler = CFRDecompiler(
            verbose=True,
            options={'custom_option': 'value'}
        )
        
        # 验证选项是否正确设置
        self.assertIn('custom_option', decompiler.options)
        self.assertEqual(decompiler.options['custom_option'], 'value')

if __name__ == '__main__':
    unittest.main()
```

## 注意事项

1. 测试脚本可能会创建临时文件和目录，完成后会自动清理
2. 某些测试可能需要较长时间执行，特别是涉及大型文件的测试
3. 为了获得更准确的测试结果，建议在相对稳定的环境中运行测试
4. 测试过程中可能会消耗较多的系统资源，特别是在使用多线程或处理大型文件时
